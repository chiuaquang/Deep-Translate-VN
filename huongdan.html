1

Chọn công cụ dịch theo engine của game

Deep Translate VN có hai công cụ riêng. Chọn đúng ngay từ đầu — mỗi engine lưu thoại theo một kiểu khác nhau, chọn sai thì tool không trích được text hoặc xuất file game không đọc được.

Khi nào chọn “Dịch RPG Maker MV / MZ”?

Mở thư mục game lên: nếu thấy thư mục www/data (bản MV) hoặc data (bản MZ) chứa nhiều file .json thì đó là game RPG Maker. Những file thường cần dịch:

Map001.json, Map002.json… CommonEvents.json Actors.json Items.json Skills.json Weapons.json Armors.json Enemies.json States.json Classes.json System.json Troops.json
  • Thoại chính nằm trong các file Map*.json và CommonEvents.json — dịch hai nhóm này trước.
  • Các file còn lại là dữ liệu tên gọi: nhân vật, vật phẩm, kỹ năng, trạng thái… trong System.json còn có các chữ hệ thống như tên tiền tệ, lệnh menu.
  • Dịch từng file một: tải một file lên, dịch xong, xuất ra, rồi mới sang file tiếp theo.

Khi nào chọn “Dịch Ren'Py”?

Mở thư mục game lên: nếu thấy thư mục game chứa các file .rpy thì đó là game Ren'Py. Những file thường cần dịch:

script.rpy story.rpy chapter1.rpy… game/tl/…/*.rpy
  • File thoại chính thường tên là script.rpy hoặc tách theo chương/hồi — dịch lần lượt từng file.
  • Nếu game đã có sẵn thư mục bản dịch game/tl/<ngôn ngữ>/ thì dịch các file .rpy trong đó là gọn nhất.
  • Chỉ dịch phần chữ trong dấu ngoặc kép — phần mã bên ngoài (tên label, lệnh scene, show…) cứ để tool tự bỏ qua, đừng sửa tay trong file gốc.
!

Chọn sai công cụ thì sao? File .json đưa vào công cụ Ren'Py (hoặc file .rpy đưa vào công cụ RPG Maker) sẽ không trích được dòng thoại nào, hoặc xuất ra file sai cấu trúc khiến game báo lỗi. Thoát ra, chọn lại đúng công cụ rồi tải file lên lại là được — file gốc của bạn không bị ảnh hưởng.

2

Tải file game lên

Sau khi đã vào đúng công cụ, đưa file cần dịch vào tool.

  1. Sao lưu file gốc trước: chép file sắp dịch ra một thư mục riêng (ví dụ Goc/). Có bản gốc để đối chiếu và khôi phục nếu cần.
  2. Trong trang tool, kéo thả file vào khung tải lên, hoặc bấm vào khung đó rồi chọn file từ máy/điện thoại.
  3. Tool đọc file và trích toàn bộ dòng cần dịch ra khung soạn thảo: thoại, lời dẫn, lựa chọn… Các đoạn mã, tên file hình/âm thanh và phần không phải lời thoại được tự động bỏ qua.
  4. Nhìn dòng thống kê: tool báo tổng số dòng trích được. Nếu báo 0 dòng, gần như chắc chắn bạn đã chọn sai công cụ ở bước 1 hoặc chọn nhầm file.
✓

Mẹo: dịch thử một file nhỏ trước (ví dụ Actors.json hoặc một file .rpy ngắn), xuất ra và thả vào game kiểm tra. Quy trình trơn tru rồi hãy dịch các file thoại dài.

3

Dịch từng dòng trong khung soạn thảo

Mỗi dòng gồm câu gốc ở trên/trái và ô nhập bản dịch ở dưới/phải. Cứ dịch lần lượt từ trên xuống để không lạc ngữ cảnh.

  • Đọc câu gốc, gõ bản dịch vào ô của đúng dòng đó. Chỉ thay phần chữ — tag và mã trong câu phải giữ nguyên (xem kỹ ở bước 4).
  • Theo dõi tiến độ: tool đếm số dòng đã dịch / còn trống và hiện thanh phần trăm, nhìn là biết còn bao nhiêu.
  • Tìm nhanh: gõ từ khóa vào ô tìm kiếm để nhảy tới dòng chứa tên nhân vật, vật phẩm… cần sửa.
  • Lọc dòng chưa dịch: bật bộ lọc “chưa dịch” để xử lý riêng những dòng còn trống, khỏi cuộn qua hàng trăm dòng đã xong.
  • Dịch chưa xong cũng không sao: xuất CSV (bước 7) để lưu lại phần đã làm, hôm sau nhập CSV vào và dịch tiếp.

Thử ngay: khung dịch mẫu

Ba dòng dưới đây chạy đúng cách tool kiểm tra tag. Dòng 2 đang bị thiếu một tag — thử gõ thêm tag còn thiếu vào cuối bản dịch của nó và xem cảnh báo biến mất.

Đã dịch: 0/3 dòng

4

Giữ nguyên tag & mã trong câu dịch

Đây là quy tắc quan trọng nhất. Tag và mã là “lệnh” cho game: tô màu chữ, chèn tên nhân vật, chờ bấm nút… Chỉ dịch phần chữ thường, phần mã giữ nguyên từng ký tự.

Ba quy tắc vàng

  1. Không dịch, không sửa, không xóa bất cứ thứ gì nằm trong tag/mã — kể cả khi nó trông giống tiếng Anh.
  2. Không thêm tag mới mà câu gốc không có, và giữ tag ở vị trí tương ứng trong câu dịch.
  3. Câu gốc có bao nhiêu tag thì câu dịch phải có đủ bấy nhiêu, mở tag nào thì phải có tag đóng của nó (ví dụ {b} … {/b}).
# Gốc (Ren'Py) sakura "Take this, {b}Star Pendant{/b}, [player_name]!" # Bản dịch đúng sakura "Cầm lấy này, {b}Mặt Dây Chuyền Sao{/b}, [player_name]!"

Chữ được dịch, còn {b}, {/b} (in đậm) và [player_name] (tên người chơi tự đặt — game tự điền) giữ nguyên y hệt.

MÃ

Mã được bảo vệ và giữ nguyên trong bản dịch

Danh sách đầy đủ các mã mà Deep Translate VN đang trích ra và bảo vệ khi dịch tự động. Các mã này không được dịch, không được sửa, không được làm mất — và phải xuất hiện y hệt trong bản dịch, đúng ký tự, đúng chữ hoa/thường, đúng số trong ngoặc và đúng vị trí tương ứng với câu gốc.

Tool bảo vệ các mã này như thế nào?

1

Trích ra trước khi gửi dịch. Tool quét câu gốc, nhận diện mọi mã trong danh sách dưới đây và thay chúng bằng mã giữ chỗ bền trước khi gửi cho Google Translate, Index Translate hay Gemini.

2

Chỉ dịch phần chữ. Nhà cung cấp dịch chỉ nhìn thấy phần lời thoại và mã giữ chỗ — phần mã gốc không bị dịch sang tiếng khác, không bị đổi số và không bị viết lại.

3

Khôi phục và tự chèn lại nếu bị mất. Dịch xong, tool gắn lại mã gốc, rồi đối chiếu lại toàn bộ mã của câu gốc với bản dịch. Mã nào vẫn bị mất sẽ được tự chèn lại: mã ở đầu câu vào đầu bản dịch, mã ở cuối câu vào cuối, mã ở giữa câu vào vị trí tương ứng ở giữa — rồi dòng mới được tính là “Đã dịch” thay vì “Thiếu tag”.

!

Tự chèn lại là lớp bảo vệ cuối, không phải lý do để xóa mã khi sửa tay. Khi bạn tự gõ hoặc sửa bản dịch, vẫn phải chép nguyên văn mã từ câu gốc. Nếu sửa tay mà thiếu mã, dòng sẽ báo “Thiếu tag” để bạn bổ sung trước khi xuất file.

Ví dụ bắt buộc phải giữ: mã ở đầu dòng

# Gốc (RPG Maker) — dòng bắt đầu bằng \dac \dac Mmm... ooh... This is nowhere near enough.... # Bản dịch đúng — vẫn phải bắt đầu bằng \dac, không được mất \dac Ùm... Ồ... Thế này thì còn lâu mới đủ.... # Bản dịch SAI — dịch đúng chữ nhưng mất \dac ở đầu Ùm... Ồ... Thế này thì còn lâu mới đủ....

Nguyên tắc này áp dụng giống hệt cho mọi mã ở mọi vị trí: \nc ở đầu dòng thì bản dịch cũng bắt đầu bằng \nc, {w} ở giữa câu thì bản dịch cũng có {w} ở giữa, mã ở cuối câu thì bản dịch kết thúc bằng đúng mã đó.

RPG Maker MV / MZ — mã được bảo vệ

Mọi mã bắt đầu bằng dấu \ dưới đây đều được giữ nguyên y hệt, kể cả số trong ngoặc vuông.

MãChức năng & cách giữ
\C[n]Đổi màu chữ — n là mã màu. Giữ đúng số, ví dụ \C[17]; thường đi cùng \C[0] ở sau để trả màu về mặc định, phải giữ cả hai.
\N[n]Tên nhân vật theo ID trong database. Game tự thay bằng tên nhân vật — không dịch chữ bên trong, không đổi số.
\V[n]Giá trị biến số trong game (số vàng, điểm, số lượng…). Game tự điền giá trị khi chạy.
\I[n]Icon theo số thứ tự trong bảng icon. Giữ đúng số — sai số là hiện sai icon hoặc mất icon.
\P[n]Tên thành viên trong đội theo vị trí trong party. Game tự thay bằng tên nhân vật tương ứng.
\GĐơn vị tiền tệ của game. Không có ngoặc số — giữ nguyên đúng hai ký tự \G.
\S[n], \FS[n] và các mã cùng họ có [n]Các mã tham số tương tự mà tool trích được (công tắc, cỡ chữ ở bản MZ…) — giữ nguyên cả tên mã lẫn số trong ngoặc.
\dacMã của plugin dùng trong nhiều game — thường đứng ở đầu dòng thoại. Giữ nguyên đúng vị trí, như ví dụ ở trên: gốc bắt đầu bằng \dac thì bản dịch cũng bắt đầu bằng \dac.
\ncMã của plugin — thường đứng đầu dòng, ngay trước tên người nói, ví dụ \nc <Asuna>. Giữ nguyên \nc và giữ nguyên cả phần tên đi kèm.

Ren'Py — tag được bảo vệ

Mọi tag trong ngoặc { }, biến trong ngoặc [ ] và mã định dạng %… dưới đây đều được giữ nguyên y hệt.

TagChức năng & cách giữ

{i} {/i}In nghiêng đoạn chữ ở giữa — giữ đủ cặp mở / đóng.
{s} {/s}Gạch ngang đoạn chữ ở giữa — giữ đủ cặp mở / đóng.
{u} {/u}Gạch chân đoạn chữ ở giữa — giữ đủ cặp mở / đóng.
{color=#ff6699} {/color}Đổi màu chữ — giữ nguyên giá trị màu sau dấu =, không dịch, không đổi mã màu, và giữ tag đóng {/color}.

Cách tự kiểm tra nhanh: đặt câu gốc và bản dịch cạnh nhau, đếm từng loại mã ở hai bên. Số lượng và thứ tự phải khớp nhau — ví dụ gốc có 1 lần \C[17] và 1 lần \C[0] thì bản dịch cũng phải có đúng 1 lần mỗi mã; gốc có cặp {b}…{/b} thì bản dịch cũng phải có đủ cặp đó.

5

Cảnh báo khi thiếu tag — đọc và sửa ngay

Mỗi khi bạn gõ bản dịch, tool đối chiếu tag trong câu dịch với câu gốc. Thiếu một tag là dòng đó hiện cảnh báo đỏ ngay lập tức.

!

Ví dụ cảnh báo: câu gốc có \C[17] nhưng bản dịch lỡ quên — dòng đó bị đánh dấu đỏ kèm tên tag bị thiếu, để bạn bổ sung trước khi xuất thay vì vào game mới phát hiện lỗi.

  1. Thấy dòng nào báo đỏ, mở câu gốc ra đếm lại tag: gốc có những tag nào, bản dịch còn thiếu tag nào.
  2. Chép nguyên văn tag bị thiếu từ câu gốc sang vị trí tương ứng trong bản dịch — đừng tự gõ lại theo trí nhớ, dễ sai số trong ngoặc (ví dụ \C[17] thành \C[71]).
  3. Kiểm tra cả tag đóng: có {b} thì phải có {/b}; có \C[17] đổi màu thì thường phải có \C[0] trả màu.
  4. Khi cảnh báo biến mất và dòng chuyển trạng thái “đủ tag” mới là xong. Đừng xuất file khi vẫn còn dòng báo đỏ.
✓

Quay lại khung dịch mẫu ở bước 3 để xem cảnh báo chạy trực tiếp: xóa thử một tag trong bản dịch là cảnh báo hiện lên ngay, gõ lại đủ là nó tắt.

✓

Dịch tự động thì tool còn tự sửa giúp bạn một bước nữa: sau mỗi dòng dịch bằng Google Translate, Index Translate hay Gemini, tool đối chiếu lại mã gốc và tự chèn lại mã bị mất đúng vị trí (đầu / giữa / cuối câu) như đã giải thích ở mục Mã được bảo vệ. Dòng vẫn báo “Thiếu tag” sau bước đó nghĩa là cần bạn kiểm tra và sửa tay như các bước trên — đừng bỏ qua.

LÔ

Batch dịch — số dòng trong một lần gọi

Khi dịch tự động bằng Model, tool không gửi từng dòng rời rạc trong mọi trường hợp mà gom thành từng lô (Batch). Hiểu và đặt đúng Batch giúp dịch nhanh hơn mà vẫn giữ được tag/mã và tránh bị chặn.

Batch là gì?

Batch là số dòng được gom lại và gửi đi trong một lần gọi dịch. Ví dụ bạn còn 61 dòng chưa dịch và đặt Batch là 20, tool sẽ chia thành 4 lần gọi: 20 + 20 + 20 + 1 dòng. Đặt Batch là 10 thì cùng 61 dòng đó thành 7 lần gọi: 10 × 6 + 1 dòng.

Bạn tự nhập được số Batch riêng cho từng nhà cung cấp trong khung “Dịch tự động bằng Model” của cả hai tool — đổi nhà cung cấp thì dùng ô Batch của nhà cung cấp đó:

Khuyên dùng: 10–20 dòng / lô

Google Translate

Ô Batch của Google Translate áp dụng khi dịch bằng Google Translate miễn phí, kể cả khi bấm “Dịch tất cả” và “Dịch hàng loạt tất cả file”.

Google là bên nhạy cảm nhất với Batch cao — xem cảnh báo ở ngay dưới.

Khuyên dùng: 10–20 dòng / lô

Index Translate

Ô Batch của Index Translate áp dụng cho cả ba model 2B (nhanh), 9B (cân bằng) và 35B-A3B (preview). Đổi model không đổi Batch — muốn đổi tốc độ lô thì sửa ngay trong ô Batch của Index.

Lô càng lớn, mỗi lần gọi càng tốn quota và càng lâu mới trả kết quả.

Khuyên dùng: 10–20 dòng / lô

Gemini Flash

Ô Batch của Gemini Flash áp dụng cho các model Gemini Flash bạn đã chọn. Prompt dịch đã lưu vẫn được dùng như bình thường cho mỗi lô.

Lô càng lớn, mỗi lần gọi càng đốt nhiều token/quota của key Gemini đang dùng.

✓

Mặc định nên để Batch từ 10 đến 20 dòng một lô. Dòng dài hoặc nhiều mã/tag thì để khoảng 10; dòng ngắn, ít tag thì để khoảng 20. Đây là khoảng cân bằng giữa tốc độ và độ an toàn cho cả ba nhà cung cấp — chưa có lý do cụ thể thì đừng tăng cao hơn.

Batch thấp (ví dụ 5–10)Ít lỗi hơn, dễ giữ đủ tag/mã, lỗi một lô thì chỉ mất ít dòng — nhưng tổng số lần gọi nhiều hơn.
Batch cao (ví dụ 40–50 trở lên)Ít lần gọi hơn trên lý thuyết — nhưng rủi ro tăng mạnh theo cảnh báo dưới đây, và khi lỗi thì thường chậm hơn cả Batch thấp.

Cảnh báo khi nhập Batch cao

!

Đừng đặt Batch cao để “dịch cho nhanh”. Batch cao gây ra các lỗi sau, và lỗi nặng nhất là với Google Translate:

  • Google trả lỗi 429 (Too Many Requests) — bị chặn tạm thời: gửi quá nhiều chữ trong thời gian ngắn khiến Google hạn chế IP của bạn. Gặp 429 thì phải chờ một lúc mới dịch tiếp được.
  • Đường dẫn (URL) quá dài: Google Translate miễn phí gửi nội dung qua URL — lô càng nhiều dòng, URL càng dài, vượt giới hạn là lần gọi đó thất bại hoặc bị cắt mất nội dung.
  • Dịch sai, lẫn dòng hoặc làm mất tag/mã: lô quá lớn khiến kết quả dễ bị trộn thứ tự các dòng, sót dòng, và mã giữ chỗ dễ bị xô lệch — tag/mã bị mất nhiều hơn, kể cả khi tool đã có bước tự chèn lại.
  • Tốn quota Gemini và Index Translate nhanh hơn: mỗi lô lớn đốt nhiều token/quota trong một lần gọi; lô lỗi phải dịch lại từ đầu lô đó, thành ra tốn gấp đôi.
  • Dịch chậm lại thay vì nhanh hơn: khi một lô lớn bị lỗi, tool phải tự chia nhỏ lô ra và thử lại từng phần, cộng thêm thời gian chờ giữa các lần thử — tổng thời gian thường lâu hơn để Batch 10–20 ngay từ đầu.

Thấy lỗi 429 hoặc mất tag thì làm gì?

  1. Giảm Batch xuống ngay — ví dụ đang để 50 thì giảm về 20, vẫn lỗi thì giảm tiếp về 10.
  2. Chờ một lúc rồi dịch lại các dòng chưa dịch (đặc biệt khi gặp 429 — bấm dịch lại liên tục ngay lập tức chỉ làm thời gian bị chặn kéo dài thêm).
  3. Sau khi giảm Batch, dùng bộ lọc “chưa dịch” và kiểm tra các dòng báo “Thiếu tag” (bước 5) trước khi dịch tiếp hoặc xuất file.
  4. File càng dài, dòng càng dài hoặc càng nhiều mã (xem danh sách mã được bảo vệ) thì càng nên ở gần mức 10 dòng / lô.
6

Xuất file đúng định dạng gốc, thêm _VI

Dịch xong (và hết cảnh báo tag), bấm nút xuất trong tool. File xuất ra giữ nguyên cấu trúc và đuôi file gốc, chỉ thêm hậu tố _VI vào tên để không đè lên file gốc.

Map001.json→ Map001_VI.json
script.rpy→ script_VI.rpy

Thả file vào game

  1. Chép file _VI vừa xuất vào đúng thư mục chứa file gốc (thư mục data với RPG Maker, thư mục game với Ren'Py).
  2. Đổi tên file bỏ hậu tố _VI, trở về đúng tên gốc — game chỉ nhận diện file theo tên gốc. File gốc cũ đã có bản sao lưu ở bước 2 nên cứ yên tâm thay.
  3. Mở game lên, chơi tới đoạn vừa dịch để kiểm tra: chữ hiển thị đúng, màu/icon đúng, không vỡ khung thoại.
!

Quên bỏ hậu tố _VI là lỗi hay gặp nhất: file nằm trong thư mục nhưng game vẫn chạy file cũ, nhìn vào tưởng “dịch rồi mà game vẫn tiếng Anh”.

7

Xuất / nhập CSV — dịch bằng Excel, Sheets hoặc chia việc

File dài hàng nghìn dòng, muốn dịch trên bảng tính hoặc chia cho nhiều người dịch chung? Dùng CSV làm “bản nháp trung gian”.

Xuất CSV

  1. Tải file game lên đúng công cụ như bình thường để tool trích các dòng cần dịch.
  2. Bấm Xuất CSV. File CSV gồm các cột: số thứ tự dòng, câu gốc, câu dịch — phần bạn đã dịch trong tool (nếu có) cũng được ghi theo.
  3. Mở CSV bằng Excel, Google Sheets hoặc LibreOffice và dịch ở cột câu dịch.

Khi dịch trên CSV — 3 điều không được đụng vào

  • Không sửa cột số thứ tự và cột câu gốc: tool dựa vào số thứ tự để ghép bản dịch trở lại đúng vị trí trong file game.
  • Không xóa, không sắp xếp lại thứ tự dòng (đừng bấm Sort trong Excel) — lệch một dòng là dịch nhầm cả đoạn sau.
  • Tag và mã trong cột câu dịch vẫn phải giữ nguyên như bước 4 — bảng tính không tự kiểm tra tag giúp bạn, lúc nhập lại tool mới báo.

Nhập CSV trở lại

  1. Vào đúng công cụ đã dùng lúc xuất CSV (RPG Maker hay Ren'Py), mở lại đúng file game gốc đó.
  2. Bấm Nhập CSV và chọn file CSV đã dịch — tool ghép từng câu dịch vào đúng dòng theo số thứ tự.
  3. Rà lại các cảnh báo thiếu tag (bước 5), sửa xong rồi xuất file _VI như bước 6.
✓

Kiểm tra trước khi thả vào game

Đi qua danh sách này mỗi lần xuất file, chỉ mất một phút mà tránh được hầu hết lỗi thường gặp.

  • ✓Không còn dòng nào hiện cảnh báo thiếu tag — đã đối chiếu đủ các mã trong mục Mã được bảo vệ (\C[n], \dac, \nc, {b}, [player_name]…).
  • ✓Nếu vừa dịch tự động: Batch đang để ở mức 10–20, và không còn lỗi 429 chưa xử lý — nếu từng gặp 429 hoặc mất tag thì đã giảm Batch và dịch lại các dòng lỗi.
  • ✓Tiến độ dịch đạt 100% — hoặc đã lọc “chưa dịch” để chắc chắn không sót dòng nào ngoài ý muốn.
  • ✓File xuất ra đúng đuôi gốc (.json hoặc .rpy) và mang hậu tố _VI.
  • ✓Đã sao lưu file gốc trước khi thay file mới vào thư mục game.
  • ✓Đã bỏ hậu tố _VI khi chép vào game, và mở game chơi thử đoạn vừa dịch.

Câu hỏi thường gặp

Dịch xong, chép vào game rồi mà vẫn hiện tiếng Anh?

Kiểm tra hai thứ: file trong thư mục game đã bỏ hậu tố _VI và trùng đúng tên gốc chưa, và bạn có chép đúng thư mục không (RPG Maker là thư mục data chứa file gốc, Ren'Py là thư mục game). Sai một trong hai là game vẫn đọc file cũ.

Vào game thấy mất màu chữ, mất icon hoặc lỗi hiển thị?

Gần như chắc chắn do thiếu hoặc sai tag trong một câu nào đó: thiếu \C[0] làm màu lan sang câu sau, sai số trong \I[…] làm icon biến mất. Mở lại file trong tool, tìm dòng báo cảnh báo tag và đối chiếu với câu gốc.

Tải file lên mà tool báo 0 dòng cần dịch?

Thường là chọn sai công cụ (file .json phải vào công cụ RPG Maker MV/MZ, file .rpy vào công cụ Ren'Py) hoặc chọn nhầm file không chứa thoại. Quay lại bước 1, chọn đúng công cụ rồi tải lại.

Một game có nhiều file thì dịch theo thứ tự nào?

RPG Maker: dịch các file Map*.json và CommonEvents.json (thoại chính) rồi tới các file dữ liệu tên gọi và System.json. Ren'Py: dịch lần lượt theo thứ tự chương — file kịch bản chính trước, các file chương tiếp theo sau. Mỗi file làm trọn một vòng: tải lên → dịch → xuất _VI → file tiếp theo.

Đặt Batch bao nhiêu là vừa? Batch cao bị lỗi 429 thì sao?

Cứ để 10–20 dòng một lô cho cả Google Translate, Index Translate và Gemini Flash — dòng dài hoặc nhiều tag/mã thì để 10. Batch cao dễ bị Google trả 429 chặn tạm thời, URL quá dài, dịch lẫn dòng, mất tag và tốn quota, rồi tool phải chia nhỏ dịch lại nên còn chậm hơn. Gặp 429 hoặc thấy nhiều dòng “Thiếu tag” thì giảm Batch xuống (về 20 rồi 10), chờ một lúc rồi dịch lại các dòng chưa dịch. Xem chi tiết ở mục Batch dịch.

Vì sao phải giữ nguyên các mã như \dac, \nc hay {nw} trong bản dịch?

Vì đó là lệnh cho game và plugin, không phải lời thoại: mất \dac / \nc ở đầu dòng, mất {nw} ở cuối câu hay mất \C[0] trả màu đều làm game hiển thị sai. Deep Translate VN bảo vệ toàn bộ các mã này khi dịch tự động và tự chèn lại nếu nhà cung cấp làm mất — danh sách đầy đủ ở mục Mã được bảo vệ và giữ nguyên. Khi sửa tay, bạn vẫn phải giữ chúng y hệt câu gốc.

Dịch dở dang, tắt máy mai dịch tiếp được không?

Được — trước khi tắt, xuất CSV để lưu toàn bộ phần đã dịch. Hôm sau mở lại đúng file game trong đúng công cụ, nhập CSV vào là các dòng đã dịch quay lại đúng vị trí, dịch tiếp phần còn lại thôi.

Sẵn sàng dịch game đầu tiên?

Chọn công cụ theo engine, kéo file vào và dịch dòng đầu tiên — phần tag và định dạng cứ để Deep Translate VN trông chừng giúp bạn.
